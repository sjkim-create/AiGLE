# [SCR-05] 스캔 일괄 채점 기획서

> **문서 성격**: [SCR-01] 채점 관리의 **스캔 일괄 채점 기획 전용 문서**다. SCR-01에는 요약 이력만 남기고 상세는 본 문서가 정본(single source)이다.
> **기술 범위**: 화면의 흐름 · 상태별 정책 · 기능 규칙만 기술한다. 색상·치수 같은 디자인 요소와 구현(함수·변수·컴포넌트) 내용은 담지 않는다.
> **동기화 규칙**: 스캔 채점 사양을 변경하면 **본 문서와 SCR-01 이력을 함께 갱신**한다.
> **연계 문서**: [TSK-02] 과제 등록(문항별 기준 장수) · [TSK-05] 답안지 서식(OCR 판독 대상)

---

  - **③ §4.5 슬롯 상태 표 정정**: `초과` 「차단하지 않는다」 · `부족` 「O (있는 장만)」 → **차단**으로 갱신. v4.3 이후 사실과 반대였다
  - **④ §4.4 신뢰도 정정**: 「확인 필요는 채점을 막지 않는다」 → **막는다**. v4.3에서 뒤집힌 규칙이 §4.4에만 옛 문장으로 남아 있었다

  - **⑥ 도달하지 않는 경로 명시**: 부분 채점·부족 장수 고지(§8.2)와 「일부만 채점된 학생」(§8.1)은 v4.3 이후 발생하지 않는다. 삭제하지 않고 **도달 불가 표시 + 존치 사유**를 달았다 — 정책이 완화되면 다시 쓰인다
  - **⑦ 미분류 경로 갱신**: 「학생 이름 비움」(v4.2에서 입력칸 폐기로 소멸) 삭제, **「교체 되돌리기」**(v4.4) 추가
  - **⑧ §8.2 용어 통일**: `덮어쓰기` → `교체`. SCR-01 v4.5 일괄 채점 완료 요약과의 관계도 명시
- **v4.4** | 2026-08-31 | **기존 답안을 답안지 카드로 승격 — 스캔과 동일 취급**
  - **① 기존 답안이 슬롯에 카드로 올라온다**: `답안 있음` 학생의 기존 답안을 연결 결과 확인 화면에 **스캔 답안지와 같은 카드 형식**으로 표시한다. 두 종류의 데이터가 한 화면에 나란히 선다
  - **② `기존 답안 교체` 칩 폐기**: 문항 제목 옆의 예고 칩을 없앤다. 기존 답안이 카드로 직접 보이므로 상태는 카드가 말한다. 대신 **교체가 끝난 뒤에만** `🔄 교체됨` 결과 표기를 단다
  - **③ 교체는 공통 메뉴로**: 카드의 **[⋯ → 파일 업로드]**(로컬 스캔본) 또는 **[⋯ → 미분류 파일]**로 교체한다. 스캔 답안지와 완전히 같은 조작이다
  - **④ 카드 내용**: 좌측 `🔍 OCR 판독` 자리를 **`📄 제출 정보`**(제출 경로 · 제출일시)로 바꾸고, 우측 `🔗 연결 결과`는 스캔 카드와 동일하게 학생·문항을 표시한다. 신뢰도 배지 자리에는 **`📄 기존 답안`** 출처 배지가 온다
  - **⑤ 기존 답안은 「장」이 아니라 「제출 1건」**: 기준 장수와 비교하지 않는다. 기존 답안이 붙은 슬롯은 항상 `연결`이며 빈 장 자리를 만들지 않는다 (§4.5)
  - **⑥ 채점 대상**: 교체하지 않고 둔 기존 답안도 **채점한다.** 교체하면 스캔본으로, 두면 기존 답안으로 채점된다
  - **⑦ 되돌리기 신설**: 교체한 스캔본을 [⋯ → 연결 해제]하면 **기존 답안 카드가 다시 올라온다.** 이 복원이 없으면 잘못 교체한 순간 그 문항이 `미지정`이 되어 채점 시작이 막히고(§5.6 v4.3) 교사에게 되돌릴 방법이 남지 않는다
  - **⑧ 기존 답안 카드에는 [연결 해제]가 없다**: 파일이 아니므로 미분류로 내려갈 자리가 없다. 공통 메뉴에서 그 항목만 감춘다
  - **⑨ 실행 직전 확인은 유지하되 집계 기준 변경**: 舊 「`답안 있음` 학생 + 장수 ≥ 1」 → **「실제로 교체된 슬롯」**. 교체하지 않은 기존 답안은 다이얼로그에 세지 않는다
  - **⑩ 채택 사유**: 舊 모델은 기존 답안이 **보이지 않는 플래그**여서, 교사는 무엇을 덮어쓰는지 모른 채 경고만 받았다. 카드로 올리면 그 자리에서 내용을 확인하고 교체 여부를 판단할 수 있다
  - **JSX**: `ScanGradingModal.jsx` — `buildExistingRow()` 신설(판별·복원 공용), `slotHasExisting` · `slotReplacedExisting` 파생, `slotStatus` 기존 답안 분기, `fileCard` 기존 답안 렌더, mock은 `답안 있음` 학생에게 스캔을 만들지 않음

  - **③ 미분류 파일은 무시**: 어느 슬롯에도 붙지 않아 채점에 관여하지 않으므로 차단 사유에서 제외한다 (§7.1 대원칙과 정합)

  - **⑤ 「확인 필요」도 차단 대상에 포함**: v4.1 §7.1의 「확인 필요는 채점을 막지 않는다」를 **폐기**한다. AI가 추정한 문항이 검증되지 않은 채 채점되면 잘못된 문항에 답안이 붙는다
  - **⑥ 부분 채점이 사라진다**: 모든 슬롯이 정상이어야 시작되므로 `부족` 상태 채점·일부 문항만 채점되는 학생이 발생하지 않는다. §8.2의 부분 채점 고지·부족 장수 고지는 **도달하지 않는 경로**가 되지만, 정책이 다시 완화될 때를 대비해 코드와 문구는 남겨 둔다
  - **⑦ 잔여 위험 (명시)**: `부족`은 **학생이 기준보다 짧게 쓴 정상 케이스**와 스캔 누락을 시스템이 구별하지 못한다. 채울 답안지가 실제로 없으면 교사에게 남는 수단이 없어 채점을 시작할 수 없다. 우회로는 **[⋯ → 연결 해제]로 뺀 뒤 다시 붙이기**가 아니라 **[TSK-02] 문항별 기준 장수 조정**뿐이다. 운영에서 이 사례가 나오면 예외 수단(빈 장 자리 「해당 없음」 표시 등) 도입을 재검토한다

## 2. 주요 사용자 흐름

1. SCR-01 미채점 탭에서 그룹 선택 → 학생 체크 → **[스캔 채점 (N명)]**

3. **[OCR 판별 시작]** → 답안지 코드·학년/반/번호·이름·문항 번호 판독 (**선택된 학생 전원이 대상**) `[v4.2]`

   - 창을 닫으면 최소화되고 FAB로 복귀한다 (§8.3) `[v4.2]`

## 3. 워크플로우 5-Step

| # | Step | 내용 |
|:--|:--|:--|
| 1 | **파일 업로드** | 다중 스캔 파일 업로드 (PDF · PNG · JPG, 파일당 20MB 이하) + `답안 있음` 고지 배너 `[v4.2]` |

| 5 | **완료** | 완료 요약 → [확인] 시 학생 상태 전환 + **「채점 확인」 탭 이동** `[v4.2]` |

- **활성**: 그룹 선택 + 학생 1명 이상 선택
- **비활성**: 백그라운드 채점이 진행 중일 때

### 모달 닫기 정책

| Step | 닫기 |
|:--|:--|
| 파일 업로드 | 즉시 닫힘 (진행한 작업 없음) |
| OCR 판별 · 연결 결과 확인 | 확인 다이얼로그 — `진행 중인 판별·검토가 초기화됩니다. 다시 파일을 업로드해야 합니다.` |
| **AI 일괄 채점 · 완료** | **최소화** `[v4.2]` — 모달을 종료하지 않고 화면에서만 숨긴다. 채점은 계속 진행되고 진행 상태·판별 결과가 모두 보존된다. 복귀는 FAB(§8.3) |

- AI 일괄 채점 단계 하단 표기: `창을 닫아도 채점은 계속 진행되며, 하단 알림으로 다시 열 수 있습니다.` `[v4.2 — 舊 「진행 중에는 창을 닫을 수 없습니다」]`
- **구현 주의**: 최소화는 `open` prop만 `false`로 내리고 **컴포넌트는 mount 상태로 유지**한다. 조건부 mount로 처리하면 진행 상태가 소실된다

## 4. 연결 모델 — 슬롯(학생 × 문항)

```
舊:  1파일  →  1학생
新:  N파일  →  1슬롯(학생 × 문항)
```

한 문항을 여러 장에 이어 쓰는 것이 **정상**이므로 한 슬롯에 1장 이상이 붙는다. **채점 단위도 슬롯**이다 — AI는 (학생, 문항) 하나에 대해 그 슬롯의 답안지 전체를 받는다.

### 4.1 기준 장수와 슬롯 수 — 계산 예시

기준 장수는 [TSK-02] 문항별 **「답안지 출력 장수 설정」**을 따른다 (미설정 시 1장).

**예시** — 학생 5명 / 문항 3개, 기준 장수 문항1 2장 · 문항2 1장 · 문항3 1장

```
1명당 답안지        = 2 + 1 + 1                = 4장
전체 슬롯 수        = 학생 5명 × 문항 3개       = 15칸
전량 제출 시 파일 수 = 5명 × 4장                = 20장
```

- **슬롯 수 ≠ 파일 수.** 문항1은 한 슬롯에 2장이 붙으므로 15칸에 20장이 들어간다
- 이 불일치가 **결손을 잡아내는 근거**다 — 파일만 세면 「어느 칸이 비었는지」를 알 수 없다

### 4.2 답안지 코드

답안지 코드는 **과제당 1개가 아니라 답안지 1장마다 1개**씩 부여된다.

```
코드 개수 = 문항별 기준 장수의 합            (문항당 최대 10장)
```

**예시** — 위 과제(문항1 2장 · 문항2 1장 · 문항3 1장) → 코드 4개

| 문항 | 코드 | 표기 |
|:--|:--|:--|
| 문항 1 | 00000594 | (1/2) |
| 문항 1 | 00000595 | (2/2) |
| 문항 2 | 00000596 | (1/1) |
| 문항 3 | 00000597 | (1/1) |

- **시스템 인쇄값**이므로 판독이 사실상 확실하다
- **타 과제 답안지 혼입 판정**: 읽어낸 코드가 이 과제의 코드 집합에 없으면 경고
- 헤더에서 접어 두고 필요할 때 펼쳐 본다. 문항이 많아도 화면을 밀지 않는다

### 4.3 판별 방식 — A안(전부 OCR) 채택 근거

**판별 출처** ([TSK-05] 답안지 서식)

| 축 | 출처 | 성격 |
|:--|:--|:--|
| **과제·장** | `답안지 코드` — 시스템 인쇄값 | 인식률 사실상 100%. 타 과제 혼입 검출 |
| **학생** | `학년/반/번호` + `이름` — 학생 손글씨 | **명단이라는 닫힌 집합과 대조**하므로 자유 텍스트 인식이 아니라 후보 선택 문제. 한 필드가 뭉개져도 다른 필드로 교차 검증 |
| **문항** | `문항 [ ]번` — 학생 손글씨 숫자 1자리 | 손글씨 중 난이도가 가장 낮은 축. 미기재·실패 시 미분류로 안전하게 빠짐 |

**파일명 규칙 불필요** — 파일명은 교사가 붙이는 것이라 스캐너 기본 출력(`scan_0001.jpg`)이면 파싱이 불가능하다. 매핑 키로 삼지 않는다.

**QR 미채택 근거 — 실패 모드의 비대칭**

```
QR   = 인쇄 시점의 진실   "이 종이는 문항2용으로 인쇄되었다"
OCR  = 작성 시점의 진실   "학생이 이 종이에 문항2라고 썼다"
```

채점에 필요한 건 **작성 시점의 진실**이다. 학생이 문항1을 예상보다 길게 써서 여분(문항2용) 답안지를 집어 쓰면 QR은 거짓을 말한다. 그리고 그 실패는 **조용하다.**

| | 실패 시 결과 |
|:--|:--|
| **OCR 실패** | 판별 못 함 → **미분류로 빠짐** → 교사에게 확인 요구 (**시끄러운 실패**) |
| **QR 오류** | 잘못된 문항에 붙어 **그대로 채점됨** → 아무도 모름 (**조용한 오류**) |

채점 결과가 학생 성적에 반영되므로 조용한 오류가 훨씬 위험하다.

> **QR 재검토 조건**: 문항별 답안지를 물리적으로 분리 배부·회수하는 운영이 자리잡고, 문항 수가 많아(5개 이상) 손글씨 문항 번호 오인식이 실측으로 문제가 될 때. 그때도 A안을 걷어내는 게 아니라 **QR을 검증 레이어로 얹어** 불일치 시 확인 대상으로 올린다

### 4.4 신뢰도 3단계

손글씨 판독은 확률적이므로 **전부 확인시키면 안 되고 애매한 것만 확인시켜야** 한다.

| 신뢰도 | 조건 | 처리 |
|:--|:--|:--|
| 🟢 **자동 확정** | 학생 2필드 이상 일치 + 답안지 코드 일치 + 문항 번호 인식 | 그대로 통과 |
| 🟡 **확인 필요** | 일부 필드만 일치, 또는 **문항을 AI가 답안 내용으로 추론** | 슬롯에 배치하되 확인 요청 |
| 🔴 **미분류** | 판별 실패 | 미분류로 이동, 채점 대상 제외 |

- 교사가 직접 학생·문항을 지정하면 **자동 확정으로 승격**된다
- **확인 필요는 채점을 막는다** `[v4.3 — 舊 「막지 않는다」 폐기]`. AI가 추정한 문항이 검증되지 않은 채 채점되면 잘못된 문항에 답안이 붙는다. 카드의 배지를 체크하면 자동 확정으로 바뀌며 해소된다

> **문항 AI 추론 (확인 필요가 생기는 경로)**: 문항 번호가 비었거나 인식 실패하면 답안 텍스트를 문항 지문·모범답안과 유사도 비교해 추정한다. 채점을 위해 어차피 답안 전문을 읽으므로 추가 비용이 거의 없다. **단독 확정은 하지 않는다** — 문항 주제가 비슷하면 오분류가 나기 때문
>
> **예시**: 학생이 문항 번호 칸을 비운 채 제출 → 읽어낸 문항 번호 없음 → AI가 내용으로 「문항 3」 추정 → `확인 필요`로 표시 → 교사가 체크하면 자동 확정

### 4.5 슬롯 상태

| 상태 | 조건 | [채점 시작] | 성격 |
|:--|:--|:--:|:--|
| **연결** | 장수 == 기준 | 통과 | 정상 |
| **초과** | 장수 > 기준 | **차단** `[v4.3]` | 중복 스캔 의심. 여분 장을 빼야 진행된다 |
| **부족** | 0 < 장수 < 기준 | **차단** `[v4.3]` | 답안지가 덜 붙었다 |
| **미지정** | 장수 == 0 | **차단** `[v4.3]` | 답안지가 없다 |

> **v4.2까지는 `초과`·`부족`을 통과시키고 완료 요약에서 고지만 했다.** v4.3에서 「데이터가 덜 갖춰진 채 채점이 확정된다」는 문제로 사전 차단으로 전환했다. 차단 규칙의 정본은 **§5.6**이다.

**판정 예시** — 문항1 기준 2장

| 연결된 장수 | 상태 | 표기 |
|:--:|:--|:--|
| 2장 | 연결 | 배지 없음 (정상은 조용히) |
| 3장 | 초과 | `초과 3/2장` |
| 1장 | 부족 | `부족 1/2장` + 비어 있는 장 자리 1칸 |
| 0장 | 미지정 | `미지정` + 비어 있는 장 자리 2칸 |

- **舊 `중복` 폐기**: 한 슬롯에 복수 파일이 정상이 되었으므로 「같은 학생에 2개 파일」은 더 이상 오류가 아니다. 중복 스캔 의심은 `초과`가 흡수한다
- **기존 답안이 붙은 슬롯은 항상 `연결`** `[v4.4]`: 기존 답안은 학생이 이미 낸 제출물이라 **「몇 장」이라는 개념이 없다.** 기준 장수와 비교하지 않고, 빈 장 자리도 만들지 않는다
- **교체는 상태가 아니라 구성의 결과** `[v4.4]`: 원래 기존 답안이 있던 슬롯인데 지금은 없다면 스캔본으로 교체된 것이다. 별도 플래그를 저장하지 않고 현재 구성만으로 도출하므로, 되돌리거나 다시 교체해도 항상 실제와 일치한다

## 5. 연결 결과 확인 화면

뷰는 **「학생 × 문항」 하나뿐**이다. v4.0의 `상태별`·`파일 목록` 뷰는 폐기했다 — 셋 다 같은 데이터를 다른 축으로 자른 것이라 교사가 어느 화면에서 무엇을 봐야 하는지 매번 고르게 만들었다.

### 5.1 화면 구성 — 좌우 2단

```
┌ 채점 학생 3명 · 총 답안지 20장 · 채점 예정 8건 ── 기준 문항1 2장 · 문항2 1장 · 문항3 1장 ┐
├──────────────────────────┬────────────────────────────────────────────────┤
│ 학생 3명 문항1(2장) 문항2(1장) 문항3(1장) │  이순정  1학년 1반 2번                      │
│ 🔴 미분류 학생·문항 미확인      1장       │  ┌ 문항 1 ─┬ 문항 2 ─┬ 문항 3 ─┐            │
│ 김순정 1학년 1반 1번  ✓   초과   ✓        │  │ 부족    │         │         │            │
│ 이순정 1학년 1반 2번 부족   ✓    ✓        │  │ 1장     │ 1장     │ 1장     │            │
│ 박순정 1학년 1반 3번  ✓    ✓  미지정      │  │ [빈 장] │         │         │            │
└──────────────────────────┴────────────────────────────────────────────────┘
```

- **좌 = 학생 목록.** 열 제목에 기준 장수 표기(`문항1(2장)`). 행의 문항 칸은 **정상이면 `✓`로 조용히, 이상만 글자로**(`초과`/`부족`/`미지정`) 드러낸다
- **미분류는 학생 행과 같은 형태의 카드**로 목록 맨 위에 둔다. 선택하면 우측에 미분류 파일이 깔린다
- **우 = 선택 학생의 문항 상세.** 문항을 **가로로 나란히** 놓아 한 학생의 전 문항을 한눈에 비교한다
- 두 영역이 **각자 스크롤**한다. 학생이 30명이어도 상세를 보러 화면을 내려갈 일이 없다

### 5.2 답안지 카드

한 장 = 한 카드. 카드는 **읽은 값**과 **연결 값**을 좌우로 나눠 보여준다.

```
┌ 1/2장  scan_0006.jpg          🟢 자동 확정  ⋯ ┐
├ OCR 판독              │ 연결 지정              ┤
│ 1학년 1반 2번 이순정   │ [이순정 (1학년 1반 2번)] │
│ 문항 1-1              │ [문항 1-1           ▾] │
└───────────────────────┴────────────────────────┘
```

- 왼쪽은 **읽은 값(수정 불가)**, 오른쪽은 **연결 지정(수정 가능)**. 같은 높이에 이름 ↔ 이름, 문항 ↔ 문항이 놓여 어긋난 곳이 바로 보인다
- **다장 문항**은 `1/2장`·`2/2장`으로 몇 장째인지 표기. 한 장짜리 문항에는 표기하지 않는다
- **학생 지정**: 목록 검색과 **이름 직접 입력**을 모두 지원한다. 정확히 일치할 때만 연결이 바뀌고, 입력 도중의 값은 텍스트만 유지한 채 `명단에 없는 이름` 경고를 띄운다 — 타이핑 도중 카드가 미분류로 빠지지 않게 하기 위함
- **문항 지정은 장 단위**: `문항 1-1 / 문항 1-2 / 문항 2 / 문항 3`
- **교사가 직접 올린 답안지**는 판독을 거치지 않았으므로 `직접 추가 · OCR 미실행`으로 표기해 자동 판별분과 구분한다


#### 연결 결과는 읽기 전용이다 `[v4.2]`

舊 v4.1은 카드 우측을 **「✏ 연결 지정」** 으로 두고 학생 이름 입력칸(자동완성)과 문항·장 셀렉트를 제공했다. v4.2에서 이를 **「🔗 연결 결과」 읽기 전용 표시**로 바꾼다.

| 값 | 표시 |
|:--|:--|
| 학생 | `{이름} ({학년반번호})` — 연결이 없으면 **`미분류 · 채점 제외`**(빨강) |
| 문항 | `{문항명}` 또는 `{문항명} N장째` — 없으면 `(미지정)` |

- 좌측 **「🔍 OCR 판독」** 과 같은 행에 좌우로 놓아 대조하는 배치는 그대로 유지한다
- **보정은 공통 메뉴(§5.4)로 일원화한다** — [연결 해제] · [미분류 파일] · [파일 업로드]. 지정 수단이 사라진 것이 아니라 입구가 하나로 모인 것이다
- **폐기 사유**: 카드마다 입력칸을 두면 「전량을 검수해 직접 지정해야 한다」는 신호를 준다. 판별은 OCR이 전담하고 교사는 **결과 확인과 예외 처리**만 하는 것이 이 화면의 설계 의도다

#### 기존 답안 카드 `[v4.4 신설]`

`답안 있음` 학생의 기존 답안은 **스캔 답안지와 같은 카드**로 슬롯에 놓인다. 형식이 같아야 두 종류를 나란히 두고 비교할 수 있다.

| 자리 | 스캔 답안지 | 기존 답안 |
|:--|:--|:--|
| 카드 제목 | 파일명 | `{학생명} 기존 답안` |
| 미리보기 [👁] | 있음 | **없음** — 스캔 파일이 아니다 |
| 우상단 배지 | 신뢰도(`자동 확정` / `확인 필요` / `미분류`) | **`📄 기존 답안`** (출처) |
| 좌측 | `🔍 OCR 판독` — 학년/반/번호 · 이름 · 문항 | **`📄 제출 정보`** — 제출 경로(파일 업로드 / 키보드 입력) · 제출일시 |
| 우측 | `🔗 연결 결과` — 학생 · 문항 | **동일** |
| 공통 메뉴 [⋯] | 파일 업로드 · 연결 해제 · 미분류 파일 | 파일 업로드 · 미분류 파일 (**연결 해제 없음**) |

- **교체**: [⋯ → 파일 업로드]로 로컬 스캔본을 올리거나, [⋯ → 미분류 파일]에서 골라 바꾼다. 교체되면 기존 답안 카드는 목록에서 사라지고 문항 제목 옆에 **`🔄 교체됨`** 이 붙는다
- **되돌리기**: 교체한 스캔본을 [⋯ → 연결 해제]하면 **기존 답안 카드가 다시 올라온다.** 스캔본은 미분류로 내려간다
- **[연결 해제]가 없는 이유**: 기존 답안은 파일이 아니므로 미분류로 내려갈 자리가 없다. 「빼는」 조작 자체가 성립하지 않는다

### 5.3 비어 있는 장 자리

기준 장수에 못 미치면 **비어 있는 장을 카드 자리로 남긴다.**

```
┌ ─ 2/2장   확인 필요 ─ ┐
│ 답안지 없음 · 채점 대상 제외 │
│ [＋ 답안지 지정…        ] │
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─┘
```

- 이미 붙은 장 번호를 빼고 앞에서부터 계산한다 — **2장 중 1장째가 비면 빈 자리가 위에 생긴다**
- `미지정`은 이 빈 자리가 기준 장수만큼 생기는 경우일 뿐이다 (별도 화면 없음)
- 자리 전체가 드래그 앤 드롭 대상

### 5.4 답안지 작업 공통 메뉴

붙은 장과 빈 장이 **같은 메뉴**를 쓴다. 구역을 점선으로 끊는다.

```
┌──────────────────────┐
│   [ 파일 업로드 ]      │  ① 버튼
│ - - - - - - - - - - -│
│   [ 연결 해제 ]        │  ② 버튼 (붙어 있을 때만)
│ - - - - - - - - - - -│
│ 미분류 파일 1장         │  ③ 목록
│   scan_0012.jpg      │
└──────────────────────┘
```

| 구역 | 붙어 있는 장 | 비어 있는 장 |
|:--|:--|:--|
| **파일 업로드** | **교체** — 새 파일을 그 자리에 붙이고 기존 파일은 목록에서 제거 | **지정** — 올린 파일을 그 자리에 붙임 |
| **연결 해제** | 미분류로 되돌림 | (없음) |
| **미분류 파일** | **맞교환** — 고른 파일이 그 자리로, 기존 파일은 미분류로 | **지정** — 고른 파일이 그 자리로 |

- 구역 순서를 「업로드 → 해제 → 목록」으로 둔 이유: 목록은 파일 수에 따라 길이가 변하므로 **아래로 내려야 버튼 위치가 흔들리지 않는다**
- 업로드분은 판독을 거치지 않으므로 **자동 확정(교사 직접 지정)**으로 처리한다
- 미분류 파일 카드에는 붙일 자리가 없으므로 **파일 삭제**만 제공한다
- **기존 답안 카드는 [연결 해제] 구역을 감춘다** `[v4.4]` — 파일이 아니라 미분류로 내려갈 수 없다. 파일 업로드·미분류 파일 두 구역만 남으며 둘 다 「교체」로 동작한다

### 5.5 확인 필요 표시 원칙

**정상은 조용히, 이상만 드러낸다.**

| 대상 | 표시 |
|:--|:--|
| 문항 영역 / 좌측 학생 목록 칸 | 확인 필요 답안지가 있거나 장수가 기준과 다르면 **테두리 강조** |
| 문항 제목 옆 | `초과 3/2장` · `부족 1/2장` · `미지정` — **정상이면 아무 표시 없음** |
| 답안지 카드 | `확인 필요` 배지 + **체크** — 체크하면 자동 확정으로 전환 |
| 비어 있는 장 자리 | `확인 필요` 배지 |

- **중복 안내 금지**: 문항 제목 옆에 `초과 3/2장`이 있으면 그 장 카드에 `초과`를 또 달지 않는다
- 확인 필요는 **그것이 필요한 지점**에만 붙인다 — 문항 제목이 아니라 해당 장 카드, 붙은 장이 없으면 빈 자리

### 5.6 채점 시작 `[v4.3 개정 — 사전 차단]`

- 라벨은 `채점 시작` 하나. 건수는 상단 요약(`채점 예정 N건`)이 담당한다
- **활성 조건: 채점 대상 ≥ 1건 이면서, 모든 슬롯이 `연결` 상태이고, 연결된 답안지에 `확인 필요`가 없을 것**

| 상황 | 시작 | 근거 |
|:--|:--:|:--|
| `초과` 슬롯 있음 | **차단** | 기준 장수를 넘겼다. 여분 장을 [⋯ → 연결 해제]로 빼면 해소된다 |
| `부족` 슬롯 있음 | **차단** | 답안지가 덜 붙었다. 빈 장 자리에서 채운다 |
| `미지정` 슬롯 있음 | **차단** | 답안지가 없다. 빈 장 자리에서 채운다 |
| `확인 필요` 답안지 있음 | **차단** | AI 추정 문항이 검증되지 않았다. 카드의 배지 체크로 해소한다 `[v4.3 — v4.1 「확인 필요는 채점을 막지 않는다」 폐기]` |
| **미분류 파일 있음** | **통과** | 어느 슬롯에도 붙지 않아 채점에 관여하지 않는다 (§7.1) |
| `답안 있음` 학생 연결 | **통과** | 실행 직전 확인 1회 후 교체 (§6.2) |

**비활성 사유 노출** — 푸터와 버튼 툴팁에 같은 문장을 쓴다.

- 대상 0건: `채점 대상이 없습니다. 학생·문항에 연결된 답안지가 한 건도 없습니다.`
- 그 외: `초과 N건 · 부족 N건 · 미지정 N건 · 확인 필요 N장을(를) 먼저 정리해 주세요. 모든 문항이 기준 장수를 채우고 확인이 끝나야 채점을 시작할 수 있습니다.` (해당하는 항목만 나열)

> **잔여 위험**: `부족`은 학생이 기준보다 짧게 쓴 정상 케이스와 구별되지 않는다. 채울 답안지가 없으면 교사가 채점을 시작할 방법이 없고, 우회로는 [TSK-02] 기준 장수 조정뿐이다. 운영 사례가 나오면 예외 수단 도입을 재검토한다.

## 6. 답안 기제출 학생 처리 — 기존 답안을 카드로 `[v4.4]`

> **문제 정의**: 스캔 채점은 교사가 종이 답안지를 시스템에 **주입**하는 행위다. 대상이 `답안 있음` 학생이면 **학생이 이미 제출한 답안이 덮어써진다.**
>
> **펜 일괄 채점과의 차이**: 펜 경로는 크래들에 펜이 없으면 「학생 미매칭」으로 자동 제외되어 자연 방어가 된다. `답안 있음` 학생은 애초에 펜을 쓰지 않은 학생이므로 펜 경로에서는 문제가 없다. 스캔은 교사가 파일을 직접 올리므로 그 방어막이 없다. **본 정책은 스캔 채점에만 적용된다.**

### 6.1 기본 방침 — 보여주고, 교사가 갈아끼운다 `[v4.4]`

핵심 전환은 **경고에서 표시로**다. 舊 모델은 기존 답안이 **보이지 않는 플래그**여서 교사는 무엇을 덮어쓰는지 모른 채 경고만 받았다. v4.4는 기존 답안을 답안지 카드로 올려 **그 자리에서 확인하고 판단**하게 한다.

- **전원 판별**: `답안 있음` 여부와 무관하게 선택된 학생 전원이 OCR 판별 대상이다
- **기존 답안이 슬롯을 채운다**: 판별이 끝나면 `답안 있음` 학생의 각 문항에 **기존 답안 카드**가 놓인다 (§5.2). 슬롯 상태는 항상 `연결`이다
- **교체는 교사의 명시적 조작**: 카드의 [⋯ → 파일 업로드] 또는 [⋯ → 미분류 파일]. 스캔 답안지와 완전히 같은 조작이다
- **두면 기존 답안으로 채점된다**: 교체하지 않은 기존 답안도 채점 대상이다. 스캔 세션이라고 해서 기존 답안을 빼두지 않는다
- **되돌릴 수 있다**: 교체한 스캔본을 [⋯ → 연결 해제]하면 기존 답안 카드가 복원된다

**舊 정책 폐기 이력**

| 버전 | 폐기 대상 | 사유 |
|:--|:--|:--|
| v4.2 | 1단 — 대상 학생 확인 (파일 업로드) | 교사가 **판별 결과를 보기도 전에** 포함/제외를 결정해야 했다. 실제로는 대부분 전원 포함이었고, 「기본 전원 제외」를 지나친 채 진행해 `채점 대상이 없습니다`로 막히는 오조작이 반복됐다 |
| v4.2 | 2단 — 문항별 [교체 승인] 토글 | 교체 문항마다 토글을 켜야 채점 대상이 되어 학급 단위 일괄 교체 시 클릭 비용이 과도했다 |
| **v4.4** | **`기존 답안 교체` 예고 칩** | 기존 답안이 카드로 직접 보이므로 칩이 하는 말을 카드가 이미 한다. 예고 대신 **교체가 끝난 뒤 `🔄 교체됨` 결과 표기**만 남긴다 |

### 6.2 표기

**파일 업로드 단계 — 고지 배너** (`답안 있음` 학생이 1명 이상일 때만)

- 제목: `이미 답안이 있는 학생 N명이 포함되어 있습니다`
- 전문: `이 학생들의 기존 답안은 연결 결과 확인 화면에 답안지 카드로 함께 표시됩니다. 그대로 두면 기존 답안으로 채점되고, 스캔본으로 바꾸려면 그 카드의 [⋯ → 파일 업로드]로 교체하세요. 교체한 건에 한해 채점 시작 시 한 번 더 확인하며, 기존 답안은 이력에 보관되어 복원할 수 있습니다.`
- 학생별 `이름 · 학년반번호 · 답안 있음` 칩을 나열한다 — **선택 컨트롤 없음**

**연결 결과 확인 단계**

- 기존 답안은 **답안지 카드**로 표시된다 (§5.2 「기존 답안 카드」)
- 교체가 끝난 문항에만 제목 옆 **`🔄 교체됨`** 표기
- 하단 안내(교체 1건 이상일 때): `N건의 기존 답안을 스캔본으로 교체했습니다. 채점 시 해당 문항의 기존 답안이 스캔본으로 바뀝니다. 되돌리려면 그 문항의 답안지를 [⋯ → 연결 해제]하세요 — 기존 답안이 다시 올라옵니다. 채점 시작 시 교체 대상을 한 번 더 확인합니다.`

### 6.3 실행 직전 확인

- **집계 기준은 「실제로 교체된 슬롯」** `[v4.4 — 舊 「답안 있음 학생 + 장수 ≥ 1」]`. 교체하지 않은 기존 답안은 세지 않는다
- 교체 대상이 1건 이상이면 다이얼로그 1회 (0건이면 생략)
- 제목: `기존 답안을 교체합니다`
- 본문:
  ```
  학생이 제출한 답안 N건이 스캔본으로 교체됩니다.
  기존 답안은 이력에 보관되며 복원할 수 있습니다.
  계속하시겠습니까?
  ```
- 보조 표기: `교체 대상: {학생명} {문항명}, …`
- 액션: **[취소]** → 연결 결과 확인 유지 / **[덮어쓰고 채점 시작]** → 채점 진행

> **왜 남겨 두는가**: 교체는 이미 교사의 명시적 조작이므로 다이얼로그는 두 번째 확인이다. 그럼에도 남기는 이유는 **여러 문항을 교체한 뒤 전체 목록을 한 번에 보는 지점**이 여기뿐이기 때문이다. 카드 단위로 하나씩 바꾸다 보면 총 몇 건을 덮어쓰는지 놓치기 쉽다.

## 7. 이상 상태와 미분류 파일 처리

> **채점 시작 차단 규칙의 정본은 §5.6이다.** 이 절은 각 상태가 **무엇이고 어떻게 해소하는지**를 다룬다. 두 곳이 어긋나면 §5.6을 따른다.

### 7.1 상태별 처리

| 상태 | 조건 | [채점 시작] | 해소 방법 |
|:--|:--|:--:|:--|
| **연결** | 장수 == 기준 | 통과 | — |
| **기존 답안** `[v4.4]` | `답안 있음` 학생, 교체하지 않음 | 통과 | — (기준 장수와 비교하지 않는다, §4.5) |
| **교체됨** `[v4.4]` | 기존 답안을 스캔본으로 바꿈 | 통과 | 되돌리려면 [⋯ → 연결 해제] — 기존 답안이 복원된다 |
| **초과** | 장수 > 기준 | **차단** | 여분 장을 [⋯ → 연결 해제]로 뺀다 |
| **부족** | 0 < 장수 < 기준 | **차단** | 빈 장 자리에서 채운다 |
| **미지정** | 장수 == 0 | **차단** | 빈 장 자리에서 채우거나, 그 학생을 선택에서 뺀다 |
| **확인 필요** | AI 문항 추정 등 | **차단** | 카드의 `확인 필요` 배지를 체크한다 |
| **미분류 파일** | 어느 슬롯에도 미연결 | **통과** | 해소하지 않아도 된다 — 채점에서 빠질 뿐이다 |

- **미분류만 차단 사유가 아닌 이유**: 채점 대상은 파일이 아니라 **슬롯**이다(§7.2). 슬롯이 모두 정상이면 남은 파일이 무엇이든 채점 결과에 영향을 주지 않는다
- **부분 채점은 발생하지 않는다** `[v4.3]`: 모든 슬롯이 `연결`이어야 시작되므로, 일부 문항만 채점된 학생·기준 장수 미달 채점이 나올 수 없다. §8.1의 「일부만 채점된 학생은 `미채점` 유지」와 §8.2의 부분 채점·부족 장수 고지는 **현재 정책에서 도달하지 않는 경로**이며, 정책이 완화될 때를 위해 정의만 남겨 둔다

**진행 예시** — 학생 5명 / 문항 3개 (기준 문항1 2장 · 문항2 1장 · 문항3 1장)

```
김순정  문항1 연결(2장) · 문항2 연결(1장) · 문항3 연결(1장)
이순정  문항1 연결(2장) · 문항2 연결(1장) · 문항3 연결(1장)
박순정  문항1 연결(2장) · 문항2 연결(1장) · 문항3 연결(1장)
홍길동  전 문항 기존 답안              ← 교체하지 않음
김민지  문항1 교체됨(스캔 2장) · 문항2·3 기존 답안

미분류 1장 → 차단하지 않음, 채점에서만 빠진다
채점 예정 = 15건 (5명 × 3문항)
채점 확인으로 이동 = 5명 (전 문항 채점 완료)
실행 직전 확인 = 1건 (김민지 문항1)
```

### 7.2 미분류 파일 — 대원칙

**어느 슬롯에도 붙지 않은 파일은 채점되지 않는다. 그러나 버려지지도 않는다.**

채점 대상은 **파일이 아니라 슬롯**이다. 파일은 슬롯에 붙어야 비로소 채점에 들어가므로, 미분류 파일은 존재하되 채점에 관여하지 않는다.

**파일이 미분류가 되는 경로**

| 경로 | 발생 시점 | 결과 |
|:--|:--|:--|
| **판별 실패** | OCR 판별 단계 | 학생 또는 문항을 못 읽음 → 미분류 |
| **연결 해제** | 교사가 공통 메뉴에서 실행 | 슬롯에서 떨어져 미분류로. 그 슬롯은 장수가 하나 줄어 `부족`/`미지정`이 된다 |
| **미분류에서 교체** | 교사가 공통 메뉴에서 다른 파일 선택 | **맞교환** — 들어온 파일이 슬롯에, 나간 파일이 미분류로 |
| **교체 되돌리기** `[v4.4]` | 교체한 스캔본을 [⋯ → 연결 해제] | 스캔본이 미분류로 내려가고 **기존 답안 카드가 복원**된다 |

> **파일 업로드(교체)로 밀려난 파일은 미분류가 아니라 목록에서 제거된다.** 교사가 「이 장을 새로 스캔했다」고 명시한 것이므로 옛 스캔본을 남길 이유가 없다. 되살리려면 다시 업로드한다.
>
> **기존 답안은 미분류로 내려가지 않는다** `[v4.4]`. 파일이 아니므로 내려갈 자리가 없다 — 교체되면 목록에서 사라지고, 되돌리면 다시 나타난다.

### 7.3 교사가 미분류를 처리하는 경로

1. **빈 장 자리에서 끌어오기** — 공통 메뉴의 미분류 파일 목록
2. **슬롯 단위 직접 업로드** — 공통 메뉴의 [파일 업로드]로 그 자리에 바로 붙인다
3. **붙은 장과 맞교환** — 공통 메뉴의 미분류 파일 목록
4. **파일 삭제** — 타 과제 답안지 혼입 등
5. **그대로 두기** — 채점에서 빠질 뿐 데이터는 유지된다

### 7.4 폐기 이력 — 부분 제출 3지선다 `[v4.2 폐기]`

舊 v4.0~v4.1은 누락 감지 시 [채점 시작] 직후 「답안이 누락된 학생이 있습니다」 다이얼로그로 3지선다(누락 학생 제외 / 있는 답안으로 채점 / 취소하고 파일 업로드)를 물었다. v4.2에서 폐기했고, v4.3에서 **누락 자체를 사전 차단**하면서 이 분기는 완전히 사라졌다.

- **선택지의 실효성 부족**: 「누락 학생 제외」는 결과적으로 그 학생이 미채점에 남는 것이고, 「있는 답안으로 채점」도 누락 문항이 미채점으로 남으므로 최종 상태가 크게 다르지 않았다. 「취소하고 파일 업로드」는 [← 파일 다시 선택]과 §5.4의 슬롯 단위 직접 업로드로 이미 가능하다
- **매핑 완료 후에는 결정할 것이 없다**: 무엇이 채점되고 무엇이 빠지는지는 §5의 연결 결과 확인 화면에 이미 전부 드러나 있다. 같은 정보를 다이얼로그로 다시 묻는 구조였다

## 8. 완료 처리 및 연계

### 8.1 학생 상태 전환 조건

- **전 문항이 채점된 학생만** `채점 확인`으로 이동한다
- **일부 문항만 채점된 학생은 `미채점` 유지** — 새 상태값(`부분 채점` 등)을 만들지 않는다. 누락 답안지를 추가 스캔해 다시 실행하면 이어서 채점된다

### 8.2 완료 요약

- 기본: `채점 문항 N건 · 학생 M명` (+ 교체가 있으면 `기존 답안 교체 K건 포함`)
- **교체 고지**: `교체된 학생의 기존 답안은 이력에 보관되며, 미채점 상세(SCR-02)에서 확인할 수 있습니다.`
- 하단 고정: `[확인]을 누르면 전 문항이 채점된 N명이 「채점 확인」 단계로 이동합니다.`

**도달하지 않는 고지** `[v4.3 이후]` — 모든 슬롯이 `연결`이어야 채점이 시작되므로(§5.6) 아래 두 고지는 현재 정책에서 노출되지 않는다. 정책이 완화될 때를 위해 문구와 구현만 남겨 둔다.

- 부분 채점 고지: `N명은 일부 문항만 채점되어 미채점 탭에 그대로 남습니다. 누락된 답안지를 스캔해 다시 실행하면 이어서 채점됩니다.`
- 부족 장수 고지: `N건은 기준 장수보다 적은 장수로 채점되었습니다. 답안지가 빠진 것이라면 해당 문항을 다시 스캔해 채점해 주세요.`

> **일괄 채점(펜 경로)과의 관계**: SCR-01 v4.5에서 일괄 채점 완료 단계도 **같은 지표**(`채점 문항 N건 · 학생 M명`)를 쓴다. 다만 펜 경로는 상태 전환이 채점 완료 시점에 이미 끝나므로 마무리 문구가 과거형(`… 이동했습니다`)이다.

### 8.3 후속 연계 — 최소화 · FAB 복귀 `[v4.2 개정]`

**최소화 → 복귀 → 확인** 3단 흐름이다.

| # | 동작 | 결과 |
|:--|:--|:--|
| 1 | `AI 일괄 채점` · `완료`에서 **창 닫기(✕)** | 모달 최소화(mount 유지) + **FAB 노출**. 채점은 계속 진행된다 |
| 2 | **FAB 클릭** | 최소화된 모달을 **다시 연다**(완료 창에 포커스). 이때 FAB는 숨긴다 |
| 3 | 완료 창 **[확인]** | 상태 전환 + **「채점 확인」 탭 자동 이동** + 모달·FAB 종료 |

- **FAB 문구** — 채점 중 `AI 가 채점하고 있어요. / 탭하여 진행 상황 보기`, 완료 `채점 완료 / 탭하여 완료 창 열기`
- **완료 전환**: 최소화 상태에서 채점이 끝나면 모달이 상위에 통지해 FAB가 「채점 완료」로 바뀐다 (`onGradingFinished`)
- **舊 흐름과의 차이**: v3.16~v4.1은 [확인] **이후에** FAB를 띄우고, 클릭하면 첫 성공 학생의 채점 상세(SCR-03)를 열었다. v4.2는 FAB의 역할을 **최소화된 창의 복귀**로 바꾸고, 상세 진입 대신 **탭 이동**으로 마무리한다
- 모달이 화면에 떠 있는 동안에는 FAB를 노출하지 않는다 (중복 표시 방지)

## 9. 스캔 파일 미리보기

- 파일 카드의 미리보기 버튼으로 답안지 원본을 확대해 본다
- 헤더에 파일명 · 용량 · 읽어낸 값(답안지 코드 · 학년/반/번호 · 이름 · 문항) · 신뢰도 표기
- **판독 영역 하이라이트**: 답안지 상단 정보 테이블 위치를 점선으로 표시해 「어디를 읽었는지」를 알린다
- **연결 결과 확인 단계에서는 미리보기 안에서 바로 학생·문항을 지정**할 수 있다 — 내용을 보면서 판단하는 흐름이 끊기지 않도록
- 이미지는 원본 렌더, PDF는 준비 중 안내(파일 자체는 채점 대상에 정상 포함)

## 10. 데이터 정책

- **답안 출처 필드 신설 필요** `[서버 연동 시]` — 「누가 넣은 답안인지」(펜 / 학생 업로드 / 키보드 / 교사 스캔)를 구분해야 덮어쓰기 이력 표기가 가능하다. 현재는 2분류만 있어 표현할 수 없다
- **문항별 답안 배열 필요** `[서버 연동 시]` — 현재 모델은 학생당 단일 답안. 슬롯(학생 × 문항 × N장) 구조를 서버가 지원해야 한다
- **답안지 코드 목록 제공 필요** `[서버 연동 시]` — 답안지 출력 시점에 발급된 장별 코드를 그대로 받아야 한다
- **기존 답안은 폐기가 아니라 이력 보관** — SCR-02에서 열람·복원
- **AI 채점 2회 카운터는 유지(공유)** — 덮어쓰기는 답안 교체이지 재채점이 아니지만, 리셋하면 무제한 재채점 우회로가 열린다

## 11. 미구현·제약

- **실 OCR 미연동** — 판별은 현재 모의 동작이다. 손글씨 인식 정확도는 실제 답안지로 검증해야 하며, 특히 `1↔7` · `3↔8` 혼동이 실측 대상이다
  - 단 **정확도가 낮아도 흐름은 그대로다.** 확인 대상이 늘어날 뿐이며, 설계는 판별기가 「필드별 값 + 신뢰도」를 준다는 전제만 필요하다
- **AI 채점 미연동** — 채점 진행은 현재 모의 동작이다
- **문항 AI 추론 미연동** — 실제 추론(답안 ↔ 문항 유사도)은 채점 연동 시 구현
- **PDF 미리보기 미지원** — 후속
- **기존 답안 비교 미리보기 미지원** — 스캔본 ↔ 학생 제출본 나란히 비교는 학생 답안 조회 연동 후
- **답안지 코드 기반 문항·장 확정 미적용** — 코드는 인쇄값이라 손글씨 문항 번호보다 판독이 안정적이다. 코드로 문항·장을 확정하면 「문항 미기재 → AI 추정 → 확인 필요」 경로가 사라진다. **현재는 코드를 표시만 하고 판별에는 쓰지 않는다**
- **답안지 코드 명칭 불일치** — [TSK-05] 서식은 `과제코드`, 본 화면은 `답안지 코드`. 장당 부여되는 값이므로 명칭 정리가 필요하다
- **`그룹명`·`선생님명(학교명)` 미판독** — 인쇄값이라 읽을 수 있으나 현재 판독 항목에 없다. 타 학급·타 교사 답안지 혼입 검출에 활용 가능
