  - **완료 처리**: 매칭 완료(`ok`) 학생만 상태 → `채점 확인`로 전환. 스킵·미매칭 학생은 `미채점` 유지
  - **완료 후 FAB 연계**: 스캔 채점도 기존 일괄 채점과 동일한 FAB 흐름 재사용

  - **실패 처리**: 기존 일괄 채점과 동일 패턴 (완료 요약에서 실패 카운트, 재시도 별도 액션)

## 2. 주요 사용자 흐름 (Happy Path)

1. 좌측 메뉴 `과제 및 채점관리 > 채점 관리` 클릭 → `/grading` 진입
2. 좌측 과제 사이드바에서 과제 선택
3. 상단 과제 정보 배너에서 제출률·완료율 확인
4. 탭(전체 / 미채점 / 채점 확인 / 결과 발송)으로 필터링
5. 학생 카드에서 [상세보기] 클릭 → SCR-02 또는 SCR-03 모달 오픈
6. SCR-03 STEP 2에서 [검토 완료] 수행 시 해당 학생은 `결과 발송 전`로 전환되어 `결과 발송` 탭으로 자동 이동
7. (선택) 미채점 탭에서 학생 체크 → [일괄 채점] 실행 → 결과 요약 확인
8. (선택) 결과 발송 탭에서 `결과 발송 전` 학생 체크 → [결과발송] 실행 → `결과 발송 완료`로 전환
9. (선택) 결과 발송 탭에서 `결과 발송 완료` 학생 체크 → [결과발송 취소] 실행 → `결과 발송 전`로 되돌림
10. (선택) 임의 탭에서 AI 등급평가 완료 학생 체크 → [일괄 과정평가] 실행 → 결과 요약 확인

### 탭 & 컨트롤 바

**control-bar 2단 레이아웃 (v3.18):**

control-bar는 다음과 같이 **세로 2단**으로 구성한다 (`flexDirection: column`):

```
┌─ control-bar ──────────────────────────────────────────────────┐
│ [미채점 (N)]  [채점 확인 (N)]  [결과 발송 (N)]                  │  ← 1단: 필터 탭 (좌측)
│ [그룹 ▾] [☑ 전체 선택] [일괄 채점 (N명)]          [▦] [☰] │  ← 2단: view-controls
└────────────────────────────────────────────────────────────────┘
```

**1단 — 필터 탭** (v3.18 「전체」 탭 폐기):
- **[미채점 (N)]** — 화면 진입 기본값
- **[채점 확인 (N)]**
- **[결과 발송 (N)]** — `결과 발송 전` + `결과 발송 완료` 포함

**2단 — view-controls** (좌측 정렬 + 뷰 토글은 우측 끝, `flexWrap: wrap` v3.20 적용):

#### 일괄 채점 진행 중 학생 표시 `[UPDATE 2.1]`

> F5 새로고침 등으로 진행 중 모달/FAB 상태가 사라져도 어느 학생이 채점 중인지 시각적으로 식별할 수 있도록, 학생 목록 자체에도 진행 표시를 노출한다. 진행 중 상세 진입은 차단되며, 진행 상태 확인은 카드/행의 시각적 표시로만 가능하다. (후속에 서버 진행 상태 복원이 구현되기 전까지의 보완 정책)

**카드 보기:**

- 진행 중 학생 카드에 **흰색 반투명 오버레이** 노출 (점선 파란 테두리)
- 오버레이 내부: 회전 스피너 + 굵은 파란색 텍스트 `"AI 채점중..."`

- 채점 완료 시 자동 해제 — 오버레이/스피너/디밍 제거, 카드의 AI 채점 등급·교사 채점 등급·상태 배지가 갱신되어 정상 카드로 복귀

**목록(리스트) 보기:** (옵션 A + B 합산)

- 옵션 A — `AI 채점` 셀의 등급값을 진행 중 칩으로 교체
  - 칩 구성: 작은 회전 스피너(12px) + `"채점중..."` 텍스트
  - 색상: 배경 `#EBF2FF`, 텍스트 `#2A75F3`

  - 행 배경 `#F8FAFC`, 텍스트 셀 `#94A3B8`로 톤 다운

- 진행 중 행의 체크박스 비활성화, [상세보기 >] 링크는 회색 disabled 처리(클릭 불가, tooltip "AI 채점이 진행 중입니다.")
- 채점 완료 시 자동 해제 — 칩/인디케이터/디밍 제거되며 AI 채점 셀에 등급값 노출, 상태 배지가 `채점 확인`로 전환

##### F5 후 채점 완료 알림 `[UPDATE 2.1]`

> F5로 인해 백그라운드 채점 FAB은 복원되지 않지만, **채점 완료 시점의 알림은 In-session FAB 완료 동작과 동일한 메시지로 보장**한다. (일괄 채점 / 개별 채점 공통)

- **표시 방식**: 화면 하단 중앙에 **완료 토스트** 노출 (FAB과 동일 위치·동일 알약형 디자인)
  - 시각: 흰 배경 + 초록 ✓ 아이콘 + 굵은 텍스트
  - 메시지: `"채점이 완료되었습니다."` (FAB 완료 상태와 동일 문구)
  - 노출 시간: 약 5초간 자동 노출 후 페이드 아웃 (또는 사용자 클릭 시 즉시 닫힘)
- **트리거**: 화면이 폴링 또는 서버 알림으로 채점 완료를 감지한 시점 (학생 상태가 `채점 확인`로 전환되는 순간)
- **카드/행 동기화**: 토스트 노출과 동시에 해당 학생 카드/행은 진행 중 표시(오버레이/칩/인디케이터)가 자동 해제되고 정상 상태로 복귀
- **다중 완료 처리**: 일괄 채점에서 여러 학생이 동시 완료되어도 토스트는 1회만 노출 (메시지는 동일 — "채점이 완료되었습니다.")
- **In-session FAB 완료와의 차이**:
  - In-session: FAB이 ✓ 상태로 변하고 사용자가 클릭하기 전까지 유지 (클릭 → 모달 자동 오픈)
  - F5 후: FAB 자체가 없으므로 토스트로 대체, 별도 모달 자동 오픈 동작 없음. 사용자가 학생 카드/행을 직접 클릭해 SCR-03 진입
- **컴포넌트 재사용**: FAB 완료 상태(`grading-fab.finished`)의 시각 토큰을 그대로 재사용하여 일관성 유지

    | 줄 | 내용 |
    |:--|:--|
    | 제목 | `일괄 채점이 완료되었습니다.` |

    - **문구가 과거형인 이유**: 펜 경로는 상태 전환이 **채점 완료 시점에 이미 끝나** 있고 버튼도 [확인]이 아니라 [닫기]다. 스캔 경로의 「[확인]을 누르면 … 이동합니다」를 그대로 쓰면 사실과 다르다

#### 펜 목록 노출 기준 및 상태 분류

> 목록 기준: **크래들에 연결된 펜 전체**. 펜 수만큼 행이 노출된다. 선택 학생 중 매칭되는 펜이 없는 학생은 목록에 노출하지 않는다.

| 상태                      | 조건                                                              | 행 표시                                                                                                                     |
| ------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| **정상 매핑**             | 펜의 번호표 그룹 = 선택 그룹이고, 선택 학생과 1:1 매칭됨          | 기본 행 스타일                                                                                                              |
| **그룹 불일치**           | 펜의 번호표 그룹 ≠ 선택 그룹                                      | 주황 경고 행 — 상태 메시지: `그룹 불일치 [감지: {감지반} → 선택: {선택반}]` (예: `그룹 불일치 [감지: 1-2반 → 선택: 1-1반]`) |
| **펜 충돌 (중복 데이터)** | 동일 펜이 다른 출석부에도 배정되어 있음                           | 경고 행 — 상태 메시지: `중복 데이터`                                                                                        |
| **학생 미매칭**           | 크래들에 연결된 펜이지만, 선택된 학생 목록에 대응하는 학생이 없음 | 회색 비활성 행 — 상태 메시지: `학생 미매칭` (채점 대상에서 제외)                                                            |

- **그룹 불일치**: 각 펜 행의 상태 컬럼에 감지반·선택반을 인라인 표시. `bulkStatus === 'ready'` 상태에서만 노출
- **펜 충돌**: 행에 "중복 데이터" 상태 뱃지 노출. 채점 실행은 차단하지 않되 교사에게 인지시킴
- **학생 미매칭**: 펜 정보(배터리·펌웨어 등)는 정상 표시하되 학생명 컬럼은 `-`로 표시. 채점 대상에서 자동 제외
- 완료 시 결과 요약 모달 표시 (성공 N명 / 실패 M명)
- [실패자 재시도] 클릭하여 실패 학생만 재실행
  - 성공: 성공한 학생은 `채점 확인` 탭으로 즉시 반영

### 스캔 일괄 채점 `[정본: SCR-05]`

> 📄 **스캔 일괄 채점의 전체 명세는 [SCR-05] 스캔 일괄 채점 문서가 정본이다.**
> 워크플로우 5-Step · OCR 매핑 정책 · 신뢰도 트리아지 · 슬롯 매트릭스 · 덮어쓰기 3단 게이트 · 부분 제출 처리 · 데이터 정책이 모두 그쪽에 있다.
> 본 절은 **SCR-01 화면에서 보이는 부분과 상호 영향만** 요약한다. 사양 변경 시 SCR-05를 먼저 갱신하고 본 절과 이력을 동기화한다.

**SCR-01에서 보이는 부분**

- **진입**: 미채점 탭 컨트롤 바 [일괄 채점 (N명)] 우측의 **[📷 스캔 채점 (N명)]** (하늘색 `#0EA5E9`)
  - 활성 조건: 그룹 선택 + 학생 1명 이상 선택 / 비활성: `isAnyBgActive`
- **대상 학생**: 체크된 학생을 모달에 넘기되, **모달은 `selectedIds`를 변경하지 않는다.** 대상 범위 축소는 모달 내부에서만 일어난다
- **`답안 있음` 학생**: 스캔 채점에서 **덮어쓰기 대상**이 되므로 모달 1단 게이트에서 기본 제외된다 (§학생 목록 상태 배지 참조)
- **완료 후 상태 전환**: **전 문항이 채점된 학생만** `채점 확인` 탭으로 이동한다. 일부 문항만 채점된 학생은 **`미채점` 탭에 그대로 남는다** — 부분 채점용 새 상태값은 만들지 않는다
- **FAB 연계**: 기존 일괄 채점과 동일. `handleScanCompleted(studentIds)` → FAB 노출 → 클릭 시 첫 성공 학생 SCR-03 자동 오픈 (v3.15 정책)

**왜 스캔에만 별도 정책이 필요한가**

펜 일괄 채점은 크래들에 해당 학생 펜이 없으면 「학생 미매칭」으로 자동 제외되어 자연 방어가 된다(§펜 목록 노출 기준). 반면 스캔은 **교사가 파일을 직접 업로드**하므로 그 방어막이 없다. 덮어쓰기·결손 판정 같은 보호 장치가 스캔 경로에만 있는 이유다.

**연계 문서**

| 문서 | 관계 |
|:--|:--|
| [SCR-05] 스캔 일괄 채점 | **정본.** 전체 명세 |
| [TSK-02] 과제 등록 | 「답안지 출력 장수 설정」 = 문항별 기준 장수 → 결손 판정 기준 |
| [TSK-05] 문답지 관리 | 답안지 서식 = OCR 판독 대상 (과제코드 인쇄값 + 문항 기재란) |

### 채점 확인 단계 일괄 버튼

**교사 전용:**

- [✓ 검토 완료 처리 (N명)] 클릭하여 선택 학생 일괄 검토 완료
  - 성공: 선택 학생의 상태가 `채점 확인` → `결과 발송 전`로 전환, "결과 발송" 탭으로 이동
  - 실패: "검토 완료 처리에 실패했습니다. 다시 시도해 주세요." 토스트
  - 조건: 체크된 학생 중 `채점 확인` 상태가 1명 이상일 때만 노출
  - 조건: 대상은 `채점 확인` 학생만 (혼합 체크 시 해당 상태 학생만 처리)

> **[↺ 미채점 처리]는 일괄 액션 미제공** — 채점 결과·교사 피드백·과정평가 결과 폐기 등 영향 범위가 큰 액션이므로 **학생 단위 신중 처리 정책**을 적용한다. 일괄 환원은 제공하지 않으며, [↺ 미채점 처리]는 **SCR-03 상세 모달 푸터 좌측**에서 학생 단위로만 실행한다. AI 채점 카운터 공유(최대 2회 정책 보존)·확인 메시지·환원 후 스캔 업로드 가능 정책은 **SCR-03 §3 「미채점 처리 버튼」** 명세를 따른다.

### SCR-01:과제 선택

- **상태 설명**: 과제가 선택되어 배너·학생 그리드가 정상 로드된 상태
- **전환 트리거**: 좌측 과제 카드 클릭 → 현재 상태 진입, URL `/grading?taskId={id}&tab=all`

#### 학생 목록 (카드/리스트 공통)

**전체 공통:**

- 채점 상태 배지 노출 (단일 선택, 카드는 좌상단 / 리스트는 `상태` 컬럼)
  - `미채점` (빨강): 과제 배포 후 **학생 답안이 없는** 상태. AI 등급평가 전
  - `답안 있음` (파랑) `[v3.24 — 舊 「OCR 제출」]`: **채점 전이지만 학생 답안이 이미 존재**하는 상태 (파일 업로드·키보드 입력 등 제출 수단 무관). AI 등급평가 전
    - `미채점`과 동일하게 `status === '미채점'`의 하위 구분(`submitType`)이며 **미채점 탭에 함께 노출**된다. 별도 탭·필터를 만들지 않는다
    - 스캔 채점 시 이 상태의 학생은 **덮어쓰기 대상**이 되므로 별도 게이트를 거친다 ([SCR-05] 스캔 일괄 채점 §6)
  - `채점 확인` (파랑): AI 등급평가 완료, 교사 검토 대기
  - `결과 발송 전` (주황): 교사 검토 완료 상태. 발송 버튼으로 발송 가능, AI 재검토로 `채점 확인`으로 되돌릴 수 있음
  - `결과 발송 완료` (초록): 학생에게 결과 발송 완료. `결과발송 취소`로만 `결과 발송 전`으로 되돌릴 수 있음
- 필기 평가 배지 (채점 상태 배지와 병행 노출)
  - `과정평가 완료` (보라): AI 과정평가가 완료된 학생 (채점 상태와 무관하게 누적 표시)
- **결과 발송 타임스탬프 표기**: `결과 발송 완료` 상태 학생에 발송 시각을 함께 노출 (예: `발송: 04.15 14:32`). 운영 문의 시 참조 용도
- **결과 발송 취소 유효기간**: 별도 제한 없음. `결과 발송 완료` 상태에서는 언제든 [결과발송 취소]를 실행해 `결과 발송 전`로 되돌릴 수 있음 `[정책 확인 필요]` (운영상 유연성 확보 기본값, 정책팀 확정 필요)
